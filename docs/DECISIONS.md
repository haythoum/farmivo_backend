# Design decisions

| # | Decision | Why | Trade-off |
|---|---|---|---|
| 1 | **Native apps** (Java Android, SwiftUI iOS) | Requested; best platform integration for push, camera, photos | Two codebases to keep in step. Both share one design and one resource registry layout to make this cheap. |
| 2 | **Python Flask backend, gunicorn under supervisor** (first built on FastAPI, ported on request) | Requested stack (Flask, supervisor); gunicorn is the standard WSGI server for it. Pydantic is kept for validation, so the API contract is unchanged. | No auto-generated OpenAPI page; `docs/API.md` is the reference. Query-string and body parsing are small hand-written helpers (`app/web.py`). |
| 3 | **MongoDB instead of Firestore** | Firestore/Firebase Storage push you toward a paid plan; MongoDB Atlas has a free tier and can be self-hosted | Extra service to run. Photos moved to GridFS because Firebase Storage needs a paid plan. |
| 4 | **Firebase kept for Auth + push** | Both free, solid on mobile, no password handling in our code | Dependency on Google for sign-in; replaceable later behind `get_current_uid`. |
| 5 | **Repository interface with 3 implementations** | Swap database without touching routers; tests run with no database | Filters beyond equality are applied in Python (fine at farm scale, revisit at tens of thousands of docs per farm). |
| 6 | **One Mongo collection per record type** (`animals`, `vaccinations`, ...) with `farm_id` | Readable in the Mongo shell and tools; first version used a single `docs` collection, which made records hard to find. The code keeps Firestore-style paths and the repository maps them | Moving from the old `docs` collection: `python -m scripts.migrate_docs`. |
| 7 | **Farm scoping from the token, no farm id in URLs** | Impossible to address another farm's data; simpler client code | One farm per user for now (`member_uids` exists for future team sharing). |
| 8 | **Generic CRUD factory on the server** | Ten record types share the same behaviour; fewer bugs | Slightly more abstraction when reading the code. |
| 9 | **Untyped JSON + resource registry in the apps** | Ten record types and ~60 fields without ten model classes, adapters and forms per platform; adding a field is one line | Less compile-time safety in the apps; the server remains the validator. |
| 10 | **Reminders owned by their source record (deterministic id)** | Always consistent: edit the date and the reminder follows; no orphans | Reminder titles are generated server-side (English). |
| 11 | **Daily cron instead of per-reminder timers** | Simple, cheap, host-agnostic | Notifications arrive at the cron hour, not at an exact time. |
| 12 | **Photos public by unguessable URL** | Works with plain image loaders and caching | Not suitable for confidential images. |
| 13 | **Dates as `YYYY-MM-DD` strings** | Time zone problems vanish for calendar concepts (birth, vaccination); sorts as text | Not for timestamps (those are ISO-8601 UTC). |
| 14 | **Branch-per-repo, nothing merged to `master`** | Review before merging; the code was not compiled in the authoring sandbox | — |
| 15 | **App identifier `com.quadralens.farmivo`** (Android package / applicationId / namespace, iOS bundle id) | Company namespace (Quadralens) so the app ships under the owner's organisation | Must match what is registered in Firebase and the stores; changing it later means re-registering the apps and a new store listing. |
| 16 | **Cattle-head logo, teal/sunflower palette, "Powered by Quadralens"** | The app is for livestock, so the identity is animal-led and earthy with a fresh teal and sunflower palette instead of a generic green leaf; attribution to the owning company | Palette lives in per-platform colour resources; keep them in step with [BRANDING.md](BRANDING.md). |
| 17 | **Photos: GridFS by default, optional MinIO bucket (`farmivo-photos`)** | The server already runs MinIO; a separate bucket and access key keeps Farmivo isolated from other apps. GridFS needs no extra setup. | Photos always pass through the API (`/v1/photos/<id>`) so the bucket stays private; switching stores later does not migrate existing photos. |
| 18 | **PyMongo pinned to `<4.11`** | The production MongoDB is 3.6 (wire version 6); PyMongo 4.11+ refuses it | Upgrade MongoDB to 4.4+ to lift the pin; the code uses only basic operations (find, insert, update `$set`, delete, one index, GridFS) that work on 3.6. |
| 19 | **Farm members with four roles and approval** (owner, manager, worker, viewer; join by invite code, approved by a manager or the owner) | Several people work on one farm; the owner decides who sees what (finance only for managers and the owner). Approval means a leaked code gives no access. One policy function (`app/permissions.py`) enforced in `get_ctx`, so every route, including future ones, is protected | One farm per person (a farm switcher would need a farm id per request). Nothing is created automatically any more: the apps must call `GET /me` and offer create or join. Old accounts become owners automatically on their first request. |
