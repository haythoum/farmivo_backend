# Backend review, 3 November 2026

Line-by-line review of `app/` and `scripts/` (every router, service, the repository, schemas, config, error handling, i18n, deploy files). Each finding is either fixed (with a regression test in `tests/test_review.py`) or listed with the reason it was left as is.

Severity: **High** = data of one farm reachable by others, or data loss. **Medium** = wrong results, abuse or privacy leaks in realistic use. **Low** = edge cases, hygiene.

## Fixed

| Severity | File | Issue | Fix |
|---|---|---|---|
| High | `services/photos.py` (GridFS) | Photo URLs used GridFS's default ObjectId, which is time-based and sequential. The photo route is public by design ("unguessable id"), so anyone with one photo URL could guess the URLs of other farms' animal photos. | New photos get a random 32-hex id (`uuid4`), like MinIO. Photos stored before keep working (ObjectId still readable); re-uploading a photo gives it a random id. |
| Medium | `routers/photos.py` | The public photo route served whatever content type was stored, without `nosniff`: a file uploaded with a forged type could be rendered as something else by a browser. | Only JPEG/PNG/WebP are served as images, anything else as `application/octet-stream`, plus `X-Content-Type-Options: nosniff`. |
| Medium | `routers/animals.py` | A replaced photo and the photo of a deleted animal stayed in storage forever (and stayed reachable by URL). | Every store has `delete(url)`; the old photo is deleted on replacement and when the animal is deleted (best effort, logged on failure). |
| Medium | `routers/animals.py` | PATCH models drop validators, so `PATCH /animals/<id>` accepted a date of birth in the future (create refused it). | The merged animal is re-validated with `AnimalBase`. |
| Medium | `routers/animals.py`, `schemas.py` | `POST /animals` accepted any `photo_url`, so a client could point an animal at an outside URL (tracking pixel, unrelated image). | `photo_url` from the body is ignored; photos only come from the upload. |
| Medium | `routers/breeding.py` | Two simultaneous "record birth" requests (double tap, retry on a slow network) could both pass the "already delivered" check and create the newborns twice. | The breeding is claimed with a compare-and-set (`update_where`) before anything is created; the second request gets 409. |
| Medium | `services/membership.py` | Two managers approving or rejecting the same request at the same moment could both succeed (e.g. one approves as Manager, the other rejects). | Approve and reject use compare-and-set on `status = pending`; the second gets 409. |
| Medium | `routers/breeding.py` | `PATCH /breedings/<id>` could set `pregnancy_status: delivered` without a birth; afterwards the birth could never be recorded (409) and no newborns existed. | 422 "Record the birth to mark a pregnancy as delivered"; only the birth endpoint sets `delivered`. |
| Medium | `utils.py`, `config.py` | "Today" was the server's date. On a server running in UTC the day changes one hour after Tunisia, so reminders were bucketed a day late between 00:00 and 01:00, "date of birth in the future" was refused or allowed at the wrong time, and default dates were off. | `today()` uses `FARMIVO_TIMEZONE` (default `Africa/Tunis`, via `zoneinfo`); an invalid zone falls back to the server date. |
| Medium | `services/reminders.py` | One farm with a broken record (e.g. an unreadable date) raised an exception and stopped the daily reminder job for every farm after it. | Each farm runs in its own `try`; failures are logged and counted in `failed_farms`. |
| Medium | `services/membership.py` | Invite codes (31^4 per prefix) could be tried without limit by any verified account, to discover farms and spam their owners with join requests. | 10 wrong codes per hour per user, then 429 `too_many_attempts` (stored in `users/<uid>.join_failures`). |
| Medium | `services/account.py` | Deleting an account left the "X wants to join" notifications (with the person's name and email) and their personal notifications in the farms. | Notifications with `subject_uid` or `for_uid` equal to the user are deleted with the account. |
| Medium | `routers/reports.py` | CSV had no byte-order mark: Excel opened Arabic and accented text as garbage. Formula escaping missed cells starting with a tab or a carriage return. | UTF-8 with BOM and `charset=utf-8`; tab and CR are escaped too. |
| Low | `schemas.py` | Money and quantities had no upper bound: `Infinity` (accepted by Python's JSON parser) or 1e300 passed validation and broke totals and the JSON answers. | Upper bounds: amounts and sale price ≤ 1e12, production quantity ≤ 1e9, feed ≤ 1e7 kg, birth weight < 5000 kg. |
| Low | `routers/farm.py` | `PATCH /farm` ignored `null`, so country and address could not be cleared (also reported by the iOS review). | `country` / `address` sent as `null` or `""` are cleared; `name` / `currency` (required) still ignore `null`. |
| Low | `services/notifier.py` | Malformed push tokens (FCM `InvalidArgumentError` "not a valid FCM registration token") were kept and retried on every push. | Removed like unregistered tokens. |
| Low | `scripts/seed_demo.py` | Demo dates used the server's date. | Uses `app.utils.today()` (farm time zone). |

## Checked, no change needed

- **Cross-farm access:** every record route goes through `get_ctx()` and a farm path (`farms/<ctx.farm_id>/…`); in MongoDB every get/update/delete filters on `farm_id` too. Notifications check `is_visible` (manager-only types, `for_uid`). Members and invite codes are manager+, transfer is owner-only, matching `ROLES_AND_MEMBERS.md`.
- **Query injection:** all ids and filter values come from URL segments, query strings (text) or pydantic-validated fields; no client dict reaches a MongoDB query.
- **Email codes:** HMAC-SHA256 with a server key, `hmac.compare_digest`, 5 attempts per code, 60 s between codes, 5 codes per hour, 15-minute expiry.
- **Errors:** unexpected exceptions return a generic translated message (500, or 503 for MongoDB); stack traces only go to the server log. Firebase token errors only log the reason.
- **MongoDB 3.6:** only `find`, `find_one`, `insert_one`, `update_one` (`$set`, conditional filter), `replace_one` (upsert), `delete_one`, `create_index`, `$in`, `count_documents` (migration script) and GridFS are used; all exist on 3.6 with PyMongo 4.10.
- **i18n:** all 98 catalog keys have English, French and Arabic with the same placeholders; every English `ApiError` text the code raises is matched by the catalog.

## Not changed (with reason)

| Severity | Where | Issue | Why not changed now |
|---|---|---|---|
| Medium | `routers/animals.py` | Two simultaneous creations with the same ear tag can both pass the "tag taken" check. | Needs a unique index on `(farm_id, ear_tag)`; creating it fails if a farm already has duplicates. To do once the data is checked: `db.animals.createIndex({farm_id: 1, ear_tag: 1}, {unique: true})`. The apps disable the save button while saving, so it needs two phones at the same second. |
| Low | `GridFsPhotoStore` | Photos uploaded before this release keep their guessable ObjectId URL. | Changing them would break the stored `photo_url`s. Re-uploading a photo (or a small migration) gives it a random id. |
| Low | `deps.get_identity` | Tokens are not checked for revocation (`check_revoked`), so a deleted or disabled Firebase account keeps working for up to one hour. | Revocation checks cost one extra call to Google per request. Deleted accounts have no data left to reach. |
| Low | `routers/animals.change_status` | A worker who marks an animal sold with a price creates an income transaction although workers cannot see finance. | Intended: recording the sale is farm work; the manager sees it in finance. |
| Low | `services/mailer.LogMailer` | Without a Mailjet key the code is written to the server log. | Documented test mode; set `MAILJET_API_KEY` in production. |
| Low | whole API | No global rate limiting (only email codes and invite codes are limited). | Put nginx `limit_req` in front of gunicorn when the HTTPS proxy is set up. |
| Low | reminder job | Two cron runs at the same moment could send a reminder twice. | Run one cron entry. |
| Low | `MongoRepository` | Member records use the uid as `_id` across farms (one farm per person). | By design; documented in `DATA_MODEL.md`. |
| Info | `deploy/supervisor/farmivo.conf`, `deploy/nginx/farmivo.conf` | Example paths `/srv/farmivo` and `api.example.com`. | Examples; the live server uses its own paths (see `DEVELOPMENT_GUIDE.md`). |

## Tests

`tests/test_review.py` (18 tests). Whole suite: 144 passed, 1 skipped (mongomock) on the in-memory repository; 144 passed on `MongoRepository` over the fake MongoDB.

## After pulling on the server

`git pull` and `sudo supervisorctl restart farmivo`. Optional: `FARMIVO_TIMEZONE` in `.env` if the farms are not in Tunisia (default `Africa/Tunis`). No migration.
